The gap

Your linter reads one file. Your type checker reads the type graph. Your test suite is too slow to run on every edit and only catches what someone wrote a test for.

None of them catch the mistakes that live between files:

Migration without a rollback

Discovered during the incident, not before it.

Undocumented config read

Deploys green, comes up undefined in production.

Route changed, spec didn't

The published contract now lies to every client.

Generated code drift

Builds fine, serves the old shape silently.

Every one passes tsc, go vet, eslint, and the tests. Every one is about ten lines of script to detect. Almost nobody writes those ten lines, because there is nowhere obvious to put them and no cheap moment to run them.

The why is the part that matters. It states the failure mode, not what the check does — so the failure is actionable by someone who did not write the check, including an agent that has never seen this repo before.

The benchmark reports what it does not measure: whether a reviewer would have caught the same defect by reading the diff, false-positive rates on real repositories, and anything about how often these defects actually occur. Run node bench/run.js — the numbers regenerate.

Why this matters more with AI in the loop

An agent writes more code per hour than you can carefully read, and it is systematically weakest exactly where these defects live: it sees the file it is editing, not the invariant three directories away. It cannot know that this repo pairs migrations with rollbacks, or that inline templates here compile at request time rather than build time — unless something tells it, every time, mechanically.

A preflight.yaml is that mechanism. It converts the institutional knowledge you re-explain in every code review into a two-second command with an exit code. Point an agent at AGENTS.md and it knows how to run the checks, read a failure, and write new ones.

Add it to a repo

npx github:jay23606/preflight init   # writes a starter preflight.yaml
npx github:jay23606/preflight        # run it

Node 18+, zero dependencies, works in any language because it shells out. The examples ship checks written in JavaScript, Python, and Go — each in the language its own repo already speaks.

A check

checks:
  - name: migration-has-rollback
    when: ["db/migrations/**/*.up.sql"]
    run: node tools/check-migrations.js {files}
    budget: 5s
    why: >
      Every up migration needs a matching down. A migration without a
      rollback is discovered during the incident, not before it.

On every agent edit

// .claude/settings.json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [{ "type": "command",
                    "command": "npx github:jay23606/preflight --working --quiet" }]
      }
    ]
  }
}
